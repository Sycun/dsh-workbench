# 整项目归档、恢复与删除

DSH 当前版本以会话为归档对象，没有移动文件夹式的项目归档 API。工作台在这个原生机制上实现整项目操作：以项目的规范目录和已关联工作区为边界，处理工作区登记内会话及工作台持有的会话。

归档时先检查活动会话和已知未核实的远端执行，再保存恢复快照，逐个归档 DSH 会话，最后移除工作区登记并标记工作台项目已归档。删除使用相同的原生处理过程，将本地登记放入可恢复的回收站。目录和会话日志不删除；默认工作区不移除登记。

恢复时在原目录重新创建或复用 DSH 工作区，重新关联并取消归档快照中的会话。工作区登记 ID 可能变化，项目 ID、目录和远端关联保持不变。恢复整个项目会恢复该快照中的全部会话，包括原先单独归档的会话。

操作中途失败时保留 `sync-error`、已处理会话与目标操作。可以重试原操作或恢复；不会报告两边已同步。项目同步期间不接收新工作，且不会强制停止活动会话。整项目操作不发送远端平台暂停、重启或删除命令。

直接在 DSH 归档该工作区全部会话，或删除其工作区登记，而工作台仍为使用中时，首页和设置页会显示提醒。工作台不会自动归档自己的记录，也不会在重启时擅自重建用户从 DSH 移除的工作区。


## 单个历史任务

alpha.16 新增任务自身的生命周期，与执行状态分开保存：`active / archived / deleted`，同步中与失败状态单独记录。历史分类同时参考所属项目：任务或项目删除时进入回收站；任务或项目归档时进入已归档。项目恢复不会覆盖任务自己的整理状态。

任务删除为可恢复的移除登记，不调用原生永久删除接口，不删除本机目录、成果或 DSH 会话日志。单独归档/删除同步归档主会话，主会话的专员记录仍可追溯。恢复到活动状态时恢复主会话；从归档区移入回收站的任务，恢复时回到归档区。

所属项目处于归档或删除状态时，先恢复项目，再恢复单个任务。归档/删除会撤销该任务的远端派工授权；未完成的任务改为暂停，恢复不会自动重派。活动会话、活动专员、未核实远端回执会阻止操作。项目操作和单项任务操作按项目串行，并与后台通知投递互斥。

项目归档快照记录之前就已归档的 DSH 会话。恢复项目时保留这些会话及单独整理过的任务，避免把已经收起的历史重新打开。同步失败保留错误和快照，可重试或恢复，不误报完成。
