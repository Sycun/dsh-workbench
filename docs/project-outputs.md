# 本机成果归档

## 数据流

1. 项目在本机创建或绑定，员工会话的 cwd 是同一目录。
2. 工作台把任务必要信息交给已配置的工具；不会同步整个项目目录。
3. 连接器返回数据先写入持久台账，再归档到项目的 `工作台产出/<任务 ID>/返回数据/`。保存成功后，台账移除该返回体的队列副本，保留文件索引、来源、时间和 SHA-256。
4. 项目内生成版本化任务记录、阶段汇报和最终报告，`manifest.json` 指向当前版本。
5. 文件型交付物需要真实存在于该项目目录中。员工通过现有工具按需取回，再登记本地路径与哈希。

来源字段记录执行端 ID、适配器、传输、服务位置或 VM 名称、远端项目标识，不包含请求认证头或登录凭据。这里只处理任务返回内容，不把 DSH 的全局记忆、系统提示和全部原生会话上下文批量复制进项目。

## 交付文件

`workbench_output_register` 的 `kind=remote` 只登记引用，表示尚未取回。若属于必交文件，默认 `required=true`，申请验收会被阻止。取回到项目后，调用 `kind=local`，将本机绝对路径放在 `location`，并将原引用放在 `sourceReference`。

本地登记检查：文件确实存在、是普通文件、真实路径位于项目目录内，并计算哈希。跨项目路径和指向项目外的符号链接会拒绝。最终验收会重新核对文件；文件内容变化需要重新登记。路径和哈希证明落盘及当前内容，来源关联与报告结论仍需人工复核。

此版本没有新增一个任意远端 URL 下载器。按需取回使用用户已接入的 DSH 工具及平台导出能力；平台只给出文件路径而没有可用的取回能力时，员工应报告未完成或请示，不能把远端引用当作本地交付。

## 失败和恢复

- 保存失败时记录 `localOutput.status=failed`；保存成功与远端任务成功是两件独立的事。
- 远端回执已经收到时保留其 accepted 状态；本地失败只重试写文件，不重派远端任务。
- 返回数据队列在落盘确认前保留原内容，崩溃后可用 `workbench_export` 或界面的“保存 / 重试落盘”继续。
- 自动产物先写入临时文件，再以独占方式发布完整内容。既有内容不同的文件不覆盖。
- 成果目录使用任务 ID 隔离，并检查目录标记和符号链接，避免写错项目或覆盖普通目录。
- 历史任务不在启动时批量搬迁，用户打开历史后可显式补存已有记录。

通用自动报告使用 Markdown。需要 Word/PDF 等交付格式时，继续使用 DSH 已有文档工具，将最终文件放到项目内并登记。
